# Bloomberg 编号中英对照 — 百度主服务、Google 备用

根据用户提供的 HAR 中的文章详情 JSON 编写，只处理以下 GET 接口返回的 HTTP 200 JSON：

```text
https://cdn-mobapi.bloomberg.com/wssmobile/v1/stories/<14位大写字母或数字的文章ID>
```

不处理首页、列表、搜索、`stories/find`、`mobapi.bloomberg.com`、网页、视频或其他 App 的接口。默认使用百度通用文本翻译 API（高级版），失败时自动使用 Google 备用。没有 AI URL、Token 或模型设置。

## 安装

在 Surge 中添加远程模块：

```text
https://raw.githubusercontent.com/nickcxm/script/main/Bloomberg/Bloomberg.Translate.sgmodule
```

启用 MITM 并信任 Surge 证书。模块只追加 `cdn-mobapi.bloomberg.com`，无需解密百度或 Google 域名。

`script-path` 固定到已验证的提交。更新时需要同时更新模块以取得新脚本地址，避免继续使用旧缓存。若仍显示旧版标签，移除旧的 Bloomberg 翻译模块再重新添加，并检查没有另一份响应脚本先匹配。

App 缓存/离线文章可能不发请求。更新后完全退出 App，打开一篇未缓存的文章测试。本模块不主动重新请求文章或清理 App 缓存。

## 编号与显示

只翻译正文 `role: "p"`。每个原文段落的所有 `parts` 及嵌套链接文字先拼接为完整文本；anchor 同时有 `text` 和嵌套 `parts` 时，以嵌套文字为准，不重复提取。不发送链接 URL 或证券元数据。

原文保留全部内容和链接，在最前面追加纯文本编号，例如：

```text
【1】First English paragraph.
【1】第一段中文。

【2】Second English paragraph.
【2】第二段中文。
```

英文和中文均保留编号，方便人工核对。中文不再作为新增 `role: "p"` 组件，而是在原段落 `parts` 末尾追加一个独立的 `role: "text"` 片段，使用单个换行分隔英文与中文。原有文字与链接不修改，避免把中文误追加进链接节点。没有“中文译文”标签；默认百度正常成功时不显示 provider；使用或尝试 Google 时仅在第一段英文后显示一次，不加在各个译文末尾。

百度按完整段落打包，汇总整篇正文，可跨越图片和相关阅读组成同一网络请求；记录每段原始位置，返回后逐段插回，不移动图片或其他组件。每批含编号、换行符与标题不超过 2000 Unicode 字符，并保守限制为 5800 UTF-8 字节。小于上限的整篇文章一次提交，长文章分为少量批次。Google-only 仍按约 1200 字符、非正文组件边界打包。请求文字以 `【1】` 等编号分隔，不依赖空行数量匹配。百度跨图片打包仅改变网络请求分组，不改变展示顺序；手动选择 Google 时图片等非正文组件仍切断批次。

长段落单独处理，拆成带同一编号的小片段，全部成功后再合并为一段中文。

## 最佳匹配与降级

1. 编号完整、唯一且属于本批次：按编号逐段对应并追加到原段落。即使返回顺序变化，也能放回原文顺序。
2. 部分编号丢失但顺序还能确认：保留可确定的对应关系，将未能分开的连续原文范围合并显示。例如 `【1】【2】` 表示一个中文块覆盖两段。
3. 编号全部缺失、重复、异常或无法确认：不丢弃成功返回的译文，将这一批作为合并中文文本追加到对应范围的最后一个原文段落，并列出其对应的原文编号；原返回内容也保留供人工核对。

兼容 `[1]`、`【1】`、`【1]`、`[1】`、`【 1 】`、`【1 】`、全角 `［１］`，以及 `【p1】` / `[ P 1 ]` 等形式。数字前后和数字之间的空格也可归一化。

编号是一种尽力匹配机制，不是 Google 的正式结构化输出保证。如果原文自身包含类似编号的引用、译文遗漏内容或标记异常，可能只能合并展示，不能保证语义完整。

百度模式中，标题以内部编号 `【0】` 放在第一批正文 `【1】` 之前，不单独发请求。成功后直接修改 JSON 的 `title` 为“英文原标题 + 换行 + 中文标题”，不在正文中新增标题段落，也不在标题上显示 `【0】`。Google-only 不翻译标题；百度失败后的 Google 备用可处理同批标题。摘要、作者、图片说明、嵌入 HTML 和其他非正文内容不翻译。

若标题与正文因编号缺失而无法分开，不强行把混合内容写入 `title`；原标题保留，合并译文在正文中列出 `【0】` 等编号供人工核对。

旧版已翻译的缓存响应会去掉过时的“中文译文”/provider 标签并补充编号；能定位原段落的旧版独立中文组件会迁移到原段落末尾。旧版合并中文块不强行拆开，而是追加到对应范围的最后一段。新获取的原始正文使用新的逐段对应机制。

## 百度高级版配置

模块参数使用英文名称和非空默认值，避免头部参数解析失败。`UNSET` 表示未配置。更新后需重新填写 `baidu_appid` 和 `baidu_key`；旧中文参数名称不会自动迁移。

安装后在 Surge 模块参数中填写：

- **provider**：`baidu`（默认）；改为 `google` 可直接使用 Google。
- **baidu_appid**：开发者信息页面的 APP ID。
- **baidu_key**：同一应用对应的密钥，不是智能云的 API Key/Secret Key。

接入用户提供的通用文本翻译接口：

```text
POST https://fanyi-api.baidu.com/api/trans/vip/translate
Content-Type: application/x-www-form-urlencoded
```

签名在本地计算 `MD5(appid + 原始q + salt + 密钥)`，之后才进行 form 编码。请求发送 APP ID、正文、salt 和签名，不直接发送原始密钥。签名实现已使用 Node 原生 MD5 和文档中的签名样例验证。

百度高级版为用户提供的 10 QPS 权益：单次文章处理内，百度最多一个请求在途，上一请求完成后才发送下一请求；仍保留 150ms 的最小发起间隔，不额外加入 600ms 等待。**这不是账号级全局限速**；App 同时加载多篇文章或其他程序使用同一 APP ID 时，合计仍可能触发频率限制。

单批采用不超过 2000 Unicode 字符的打包上限（包含标题、编号和换行符），并额外校验百度的字符/UTF-8字节长度不超过 6000。按你提供的高级版权益，免费量为每月 100 万字符，超出可能按 49 元/100 万字符计费。编号、空格等也在请求文本内，使用量以百度控制台为准。

## 主备切换

百度凭证缺失、HTTP/网络错误、超时、业务错误或无法解析返回时，该文本自动使用 Google 备用，并在第一段后说明百度问题和备用行为。检测到一个百度服务错误后停止当前脚本中的新百度请求，避免持续调用失败接口；已经在途的请求可能仍完成。下一次文章请求重新尝试百度。

百度单次尝试最多约 4.5 秒，预留 Google 回退时间；Google 备用最多 3 路并发。若两者都失败，则保留编号原文并提示错误。没有自动重试百度，也不会循环切换服务。

切换只发送相同的编号正文；百度密钥、APP ID、签名不发送给 Google。百度正常成功时不显示服务说明；发生 Google 备用、百度与 Google 混用或手动选择 Google 时，第一段英文后显示一次服务说明。错误仍显示：无 provider 的情况下显示错误提示，有 provider 时合并在同一说明中。若两者均失败或没有新请求，也会明确说明，避免把配置的服务误写为实际成功服务。

## 错误与参数

| 参数 | 默认 | 行为 |
| --- | --- | --- |
| enabled | `true` | 关闭后完全放行原响应 |
| provider | `baidu` | 百度优先、Google 备用；`google` 直接使用 Google |
| baidu_appid | `UNSET` | 百度开发者应用 APP ID |
| baidu_key | `UNSET` | 对应应用的密钥，仅用于本地签名 |
| remove_ad_config | `true` | 删除 `adParams`，已有 `disableAds` 布尔字段设为 true |
| debug | `false` | 输出匹配统计、请求数量和版本；不输出正文或凭证 |

主备请求均失败时保留编号原文，在第一段后追加错误提示，例如 HTTP 429、网络失败、超时或返回内容无法解析。错误提示不参与下次翻译。匹配降级本身不会被当作翻译失败，已取得的译文继续展示。

HAR 样本中的 webview 是相关阅读，没有明确的广告组件，因此保留。广告配置清理不保证所有广告消失。

## 网络、隐私与限制

Google 备用使用无需 API key 的端点：

```text
https://translate.googleapis.com/translate_a/single?client=gtx&sl=en&tl=zh-CN&dt=t&q=...
```

正常情况下百度收到带编号的英文正文，回退或手动选择 Google 时 Google 也会收到正文。这不是离线翻译。接口可能限流、改变或停止服务，不具有正式 Google Cloud Translation API 的稳定性承诺。

不要公开分享填入百度密钥后的模块配置。源码和说明不包含真实凭证；Surge 本地配置中由用户保存凭证。

不转发 Bloomberg Cookie、Authorization、设备信息、文章 URL 或原请求头；不使用 Worker、持久化缓存、动态代码加载或通知 API。新请求设置独立请求头并关闭自动重定向和 Cookie 处理。建议使用 Surge iOS 5.9.0+ / Mac 5.5.0+。

脚本不记录正文，但 Google 请求的 `q` 可能在 Surge 请求查看器中显示正文，完整请求记录不应公开分享。

响应上限 1 MiB、最多 500 个组件、最多 48 个翻译调用单元（主备切换可能产生更多网络请求）；百度严格串行，Google 最多 3 路并发；百度每批不超过 2000 Unicode 字符/5800 UTF-8 字节；Google 每批约 1200 Unicode 字符。全局预算 45 秒，单次请求最多 7 秒，模块超时 60 秒。超出预算或请求限制的内容保留原文并提示。

文章响应需要等待翻译完成，没有跨请求缓存。修改后移除旧压缩/长度和 ETag 等字段，设置 `Cache-Control: no-store`；App 自身仍可能缓存正文。
